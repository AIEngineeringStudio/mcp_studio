[FastMCP](https://gofastmcp.com/servers/auth/token-verification?utm_source=chatgpt.com)

# 1. Authentication vs Authorization

These terms are not interchangeable.

```text
Authentication
└── Who is making the request?

Authorization
└── What may that identity do?
```

Our permission model will be:

| Token | Scopes | Capabilities |
|---|---|---|
| Reader | `calc:read` | Read resources and prompts |
| Writer | `calc:read`, `calc:write` | Read context and call calculation tools |

FastMCP requires a valid token at the HTTP transport boundary when an authentication provider is configured. Component-level authorization checks can then hide and deny components based on token scopes. [FastMCP](https://gofastmcp.com/servers/authorization)

# 3. Create Local Secrets

Create the directory:

```bash
mkdir -p secrets
```

Generate two bearer tokens:

```bash
openssl rand -hex 32 > secrets/mcp_read_token.txt
openssl rand -hex 32 > secrets/mcp_write_token.txt
```

`openssl rand` uses a cryptographically secure random-number generator, and `-hex` encodes the generated bytes as hexadecimal text. [OpenSSL Documentation](https://docs.openssl.org/3.1/man1/openssl-rand/?utm_source=chatgpt.com)

Restrict local access:

```bash
chmod 600 \
  secrets/mcp_read_token.txt \
  secrets/mcp_write_token.txt
```

Do not print these files into logs or paste them into source code.

# 4. Generate a Local TLS Certificate

Generate a self-signed certificate valid for `localhost` and `127.0.0.1`:

```bash
openssl req \
  -x509 \
  -newkey rsa:2048 \
  -sha256 \
  -days 30 \
  -noenc \
  -keyout secrets/localhost.key \
  -out secrets/localhost.crt \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
```

Restrict the private key:

```bash
chmod 600 secrets/localhost.key
chmod 644 secrets/localhost.crt
```

`openssl req -x509` can create a self-signed test certificate. `-newkey` generates the private key, `-addext` adds the required subject alternative names, and `-noenc` leaves the key unencrypted so Nginx can start unattended. OpenSSL deprecated the older `-nodes` spelling in favor of `-noenc`. [OpenSSL Documentation](https://docs.openssl.org/3.5/man1/openssl-req/)

This certificate is for local development. A public deployment needs a certificate issued by a trusted certificate authority.

# 6. Add Structured Application Logging

Create `observability.py`:

```python
from __future__ import annotations

import json
import logging
import re
import sys
import time
import uuid
from contextvars import ContextVar
from datetime import datetime, timezone
from typing import Any, Awaitable, Callable, MutableMapping


request_id_context: ContextVar[str] = ContextVar(
    "request_id",
    default="-",
)

REQUEST_ID_PATTERN = re.compile(r"^[a-f0-9]{32}$")


class JsonFormatter(logging.Formatter):
    """Format application log records as one JSON object per line."""

    EXTRA_FIELDS = (
        "request_id",
        "method",
        "path",
        "status_code",
        "duration_ms",
        "client_ip",
        "outcome",
        "operation",
    )

    def format(self, record: logging.LogRecord) -> str:
        payload: dict[str, Any] = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "request_id": getattr(
                record,
                "request_id",
                request_id_context.get(),
            ),
        }

        for field in self.EXTRA_FIELDS:
            value = getattr(record, field, None)

            if value is not None:
                payload[field] = value

        if record.exc_info is not None:
            payload["exception"] = self.formatException(
                record.exc_info
            )

        return json.dumps(
            payload,
            ensure_ascii=False,
            separators=(",", ":"),
        )


def configure_application_logging() -> None:
    """Configure structured logs for application-owned loggers."""

    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JsonFormatter())

    application_logger = logging.getLogger("mcp_service")
    application_logger.handlers.clear()
    application_logger.addHandler(handler)
    application_logger.setLevel(logging.INFO)
    application_logger.propagate = False


class RequestContextMiddleware:
    """Add correlation context without buffering request or response bodies."""

    def __init__(
        self,
        app: Callable[
            [
                MutableMapping[str, Any],
                Callable[[], Awaitable[MutableMapping[str, Any]]],
                Callable[
                    [MutableMapping[str, Any]],
                    Awaitable[None],
                ],
            ],
            Awaitable[None],
        ],
    ) -> None:
        self._app = app
        self._logger = logging.getLogger(
            "mcp_service.http"
        )

    async def __call__(
        self,
        scope: MutableMapping[str, Any],
        receive: Callable[
            [],
            Awaitable[MutableMapping[str, Any]],
        ],
        send: Callable[
            [MutableMapping[str, Any]],
            Awaitable[None],
        ],
    ) -> None:
        if scope["type"] != "http":
            await self._app(scope, receive, send)
            return

        request_id = self._resolve_request_id(scope)
        context_token = request_id_context.set(request_id)

        started_at = time.perf_counter()
        status_code = 500
        error: Exception | None = None

        async def send_wrapper(
            message: MutableMapping[str, Any],
        ) -> None:
            nonlocal status_code

            if message["type"] == "http.response.start":
                status_code = int(message["status"])

            await send(message)

        try:
            await self._app(
                scope,
                receive,
                send_wrapper,
            )
        except Exception as exc:
            error = exc
            raise
        finally:
            duration_ms = round(
                (time.perf_counter() - started_at) * 1000,
                2,
            )

            client = scope.get("client")
            client_ip = (
                str(client[0])
                if client is not None
                else "-"
            )

            extra = {
                "request_id": request_id,
                "method": scope.get("method", "-"),
                # Log the path but not the query string.
                "path": scope.get("path", "-"),
                "status_code": status_code,
                "duration_ms": duration_ms,
                "client_ip": client_ip,
                "outcome": (
                    "error"
                    if error is not None
                    else "success"
                ),
            }

            if error is None:
                self._logger.info(
                    "http_request_complete",
                    extra=extra,
                )
            else:
                self._logger.error(
                    "http_request_failed",
                    extra=extra,
                    exc_info=(
                        type(error),
                        error,
                        error.__traceback__,
                    ),
                )

            request_id_context.reset(context_token)

    @staticmethod
    def _resolve_request_id(
        scope: MutableMapping[str, Any],
    ) -> str:
        for raw_name, raw_value in scope.get(
            "headers",
            [],
        ):
            if raw_name.lower() != b"x-request-id":
                continue

            candidate = raw_value.decode(
                "ascii",
                errors="ignore",
            ).lower()

            if REQUEST_ID_PATTERN.fullmatch(candidate):
                return candidate

        return uuid.uuid4().hex
```

FastAPI middleware runs around every request and response. A raw ASGI middleware is used here rather than code that reads or reconstructs bodies, so it does not accumulate an MCP event stream in memory. [FastAPI](https://fastapi.tiangolo.com/tutorial/middleware/)

The request ID is validated before it enters logs. This prevents callers from inserting arbitrary line breaks or oversized values into log records.

```python
def read_required_secret(
    path: Path,
    description: str,
) -> str:
    try:
        value = path.read_text(
            encoding="utf-8",
        ).strip()
    except OSError as exc:
        raise RuntimeError(
            f"Could not read {description} from {path}."
        ) from exc

    if not value:
        raise RuntimeError(
            f"{description} at {path} is empty."

    return value
```

# 9. Keep Health Endpoints Outside MCP Authentication

The endpoints remain:

```text
/health/live
/health/ready
```

They do not expose calculation data or credentials, and container health checks need to reach them without an MCP bearer token.

However, this is an operational choice—not a universal security rule.

For a public deployment, use one of these patterns:

```text
Private health listener
Load-balancer-only network access
Firewall allowlist
Separate management port
```

Do not return database URLs, filesystem paths, stack traces, versions, environment variables, or credentials from health endpoints.

# 10. Replace the Nginx Configuration

Replace `nginx/default.conf`:

```nginx
# ---------------------------------------------------------------------------
# Shared HTTP-level configuration
# ---------------------------------------------------------------------------

log_format mcp_json escape=json
    '{'
        '"timestamp":"$time_iso8601",'
        '"request_id":"$request_id",'
        '"remote_addr":"$remote_addr",'
        '"method":"$request_method",'
        '"uri":"$uri",'
        '"status":$status,'
        '"bytes_sent":$body_bytes_sent,'
        '"request_time":$request_time,'
        '"upstream_addr":"$upstream_addr",'
        '"upstream_status":"$upstream_status",'
        '"upstream_time":"$upstream_response_time"'
    '}';

# Coarse edge protection by source IP.
limit_req_zone
    $binary_remote_addr
    zone=mcp_per_ip:10m
    rate=10r/s;


upstream mcp_backend {
    server app:8000;
    keepalive 16;
}


# ---------------------------------------------------------------------------
# Plain HTTP redirects to TLS
# ---------------------------------------------------------------------------

server {
    listen 8080;
    server_name localhost 127.0.0.1;

    return 308 https://$host:8443$request_uri;
}


# ---------------------------------------------------------------------------
# TLS entry point
# ---------------------------------------------------------------------------

server {
    listen 8443 ssl;
    server_name localhost 127.0.0.1;

    ssl_certificate
        /run/secrets/tls_certificate;

    ssl_certificate_key
        /run/secrets/tls_private_key;

    ssl_session_cache shared:TLS:10m;
    ssl_session_timeout 10m;

    access_log /dev/stdout mcp_json;
    error_log /dev/stderr warn;

    server_tokens off;

    client_max_body_size 1m;

    add_header
        X-Content-Type-Options
        "nosniff"
        always;

    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For
        $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # Correlation identifier generated at the edge.
    proxy_set_header X-Request-ID $request_id;

    # Return the same identifier even for Nginx-generated errors.
    add_header X-Request-ID $request_id always;

    proxy_set_header Connection "";
    proxy_redirect off;

    # ------------------------------------------------------------------
    # MCP
    # ------------------------------------------------------------------

    location = /mcp {
        limit_req
            zone=mcp_per_ip
            burst=20
            nodelay;

        limit_req_status 429;

        proxy_pass http://mcp_backend;

        proxy_buffering off;
        proxy_request_buffering on;
        proxy_cache off;

        proxy_connect_timeout 5s;
        proxy_send_timeout 60s;
        proxy_read_timeout 3600s;
    }

    # ------------------------------------------------------------------
    # Operational health
    # ------------------------------------------------------------------

    location = /health/live {
        proxy_pass http://mcp_backend;

        proxy_connect_timeout 2s;
        proxy_read_timeout 5s;
    }

    location = /health/ready {
        proxy_pass http://mcp_backend;

        proxy_connect_timeout 2s;
        proxy_read_timeout 5s;
    }

    location / {
        return 404;
    }
}
```

Nginx TLS uses a certificate and corresponding private key; the private key must remain restricted while still readable by the Nginx master process. Nginx’s current defaults support TLS 1.2 and 1.3 on recent versions. [Nginx](https://nginx.org/en/docs/http/configuring_https_servers.html?utm_source=chatgpt.com)

Nginx’s `limit_req` module uses a shared-memory leaky-bucket limiter. The configured policy averages ten new MCP HTTP requests per second per source IP and permits a burst of twenty before returning `429`. [Nginx](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)

This is only **coarse abuse protection**:

```text
Rate limiting
≠ authentication
≠ authorization
≠ per-customer quota
≠ billing enforcement
```

When Nginx sits behind another load balancer, `$remote_addr` may represent that load balancer rather than the end user. Real-client address processing must be configured only for explicitly trusted upstream proxies before using source IP as a rate-limit key.

# 11. Why the Authorization Header Is Not Logged

Nginx forwards ordinary request headers upstream by default, including:

```text
Authorization: Bearer ...
```

Our custom access log intentionally omits:

```text
Authorization
Cookie
request body
query string
```

The application middleware also logs only the normalized path, not the query string or headers.

Professional wording:

> “Credentials are operational inputs, not observability fields.”

# 12. Do Not Enable HSTS in This Local Lab

Do not add:

```nginx
Strict-Transport-Security
```

to a local self-signed deployment.

HSTS tells clients to insist on HTTPS for future connections. It should be enabled only after the real domain, trusted certificate lifecycle, subdomains, and rollback plan are confirmed. Nginx documents HSTS as a persistent client-side policy, not merely another decorative response header. [NGINX Community Blog](https://blog.nginx.org/blog/http-strict-transport-security-hsts-and-nginx?utm_source=chatgpt.com)

# 16. Create `test_secure_client.py`

```python
from __future__ import annotations

import asyncio
from pathlib import Path

from fastmcp import Client
from fastmcp.exceptions import ToolError


PROJECT_ROOT = Path(__file__).resolve().parent

MCP_URL = "https://localhost:8443/mcp"

CERTIFICATE_FILE = (
    PROJECT_ROOT
    / "secrets"
    / "localhost.crt"
)

READ_TOKEN_FILE = (
    PROJECT_ROOT
    / "secrets"
    / "mcp_read_token.txt"
)

WRITE_TOKEN_FILE = (
    PROJECT_ROOT
    / "secrets"
    / "mcp_write_token.txt"
)


def read_secret(path: Path) -> str:
    value = path.read_text(
        encoding="utf-8",
    ).strip()

    if not value:
        raise RuntimeError(
            f"Secret file is empty: {path}"
        )

    return value


async def verify_reader_access(
    token: str,
) -> None:
    async with Client(
        MCP_URL,
        auth=token,
        verify=str(CERTIFICATE_FILE),
    ) as client:
        tools = await client.list_tools()
        prompts = await client.list_prompts()
        templates = await client.list_resource_templates()

        print(
            "Reader-visible tools:",
            [tool.name for tool in tools],
        )

        print(
            "Reader-visible prompts:",
            [prompt.name for prompt in prompts],
        )

        print(
            "Reader-visible resource templates:",
            [
                template.name
                for template in templates
            ],
        )

        history = await client.read_resource(
            "history://calculations/recent/10"
        )

        print(
            "Reader can read history:",
            bool(history),
        )

        try:
            await client.call_tool(
                "add",
                {
                    "a": 20,
                    "b": 22,
                },
            )
        except ToolError as exc:
            print(
                "Reader write correctly denied:",
                exc,
            )


async def verify_writer_access(
    token: str,
) -> None:
    async with Client(
        MCP_URL,
        auth=token,
        verify=str(CERTIFICATE_FILE),
    ) as client:
        tools = await client.list_tools()

        print(
            "Writer-visible tools:",
            [tool.name for tool in tools],
        )

        result = await client.call_tool(
            "add",
            {
                "a": 20,
                "b": 22,
            },
        )

        print(
            "Writer calculation result:",
            result.data,
        )


async def verify_missing_token_is_rejected() -> None:
    try:
        async with Client(
            MCP_URL,
            verify=str(CERTIFICATE_FILE),
        ) as client:
            await client.list_tools()
    except Exception as exc:
        # This is a diagnostic integration script.
        # The connection may surface through a transport-specific
        # exception type depending on the installed MCP SDK version.
        print(
            "Unauthenticated request rejected:",
            type(exc).__name__,
        )


async def main() -> None:
    read_token = read_secret(READ_TOKEN_FILE)
    write_token = read_secret(WRITE_TOKEN_FILE)

    await verify_missing_token_is_rejected()
    await verify_reader_access(read_token)
    await verify_writer_access(write_token)


if __name__ == "__main__":
    asyncio.run(main())
```

FastMCP clients accept a bearer token through the `auth` argument and automatically construct the `Authorization: Bearer` header. The `verify` argument can point to a custom CA or certificate file for local TLS verification. [FastMCP](https://gofastmcp.com/clients/auth/bearer)

Do not use:

```python
verify=False
```

except for a deliberately isolated debugging experiment. Loading the local certificate preserves actual server-certificate verification.

# 21. Rate-Limit Probe

Create `probe_rate_limit.py`:

```python
from __future__ import annotations

import asyncio
from collections import Counter
from pathlib import Path

import httpx


PROJECT_ROOT = Path(__file__).resolve().parent

URL = "https://localhost:8443/mcp"

CERTIFICATE_FILE = (
    PROJECT_ROOT
    / "secrets"
    / "localhost.crt"
)

TOKEN_FILE = (
    PROJECT_ROOT
    / "secrets"
    / "mcp_write_token.txt"
)


async def send_request(
    client: httpx.AsyncClient,
    token: str,
) -> int:
    response = await client.post(
        URL,
        headers={
            "Authorization": f"Bearer {token}",
            "Accept": (
                "application/json, "
                "text/event-stream"
            ),
            "Content-Type": "application/json",
        },
        # Deliberately invalid MCP payload.
        # We are testing the edge limiter, not MCP behavior.
        json={},
    )

    return response.status_code


async def main() -> None:
    token = TOKEN_FILE.read_text(
        encoding="utf-8",
    ).strip()

    async with httpx.AsyncClient(
        verify=str(CERTIFICATE_FILE),
        timeout=10.0,
    ) as client:
        statuses = await asyncio.gather(
            *[
                send_request(client, token)
                for _ in range(50)
            ]
        )

    print(Counter(statuses))


if __name__ == "__main__":
    asyncio.run(main())
```

Run:

```bash
uv run python probe_rate_limit.py
```

Expected shape:

```text
Counter({
    400: ...,
    429: ...
})
```

The `400` responses come from deliberately invalid MCP payloads. The `429` responses prove Nginx rejected excess requests before they reached the application.

Exact counts are nondeterministic because connection scheduling and timing affect the leaky-bucket state.

# 23. Security Limitations That Still Remain

This stack is meaningfully safer, but it is not yet a complete public production system.

## Static tokens cannot expire

A static token remains valid until you replace it and restart or reload the application.

There is no built-in:

```text
Expiration
Revocation
Refresh flow
User consent
Identity-provider audit trail
Dynamic client registration
OAuth discovery
```

FastMCP explicitly restricts static token verification to development and testing. [FastMCP](https://gofastmcp.com/servers/auth/token-verification?utm_source=chatgpt.com)

## One leaked writer token grants all writes

All holders of the writer token share one identity:

```text
client_id = local-writer
```

You cannot distinguish individual humans, devices, or applications.

## IP rate limiting is coarse

Several legitimate clients behind one NAT gateway share the same limit. One client using several source addresses may evade it.

## Health endpoints remain reachable

They disclose only minimal status, but they are still public on the current listener.

## Logs are sensitive operational data

They contain client addresses, timing, component paths, and failure details. Log access and retention need their own policy.

## SQLite remains the scaling boundary

TLS and authentication do not change the database’s write-concurrency limitations.

# 24. Production Authentication Migration

For an internal service with an existing identity provider, replace the static verifier with JWT validation:

```python
from fastmcp.server.auth.providers.jwt import JWTVerifier


auth_provider = JWTVerifier(
    jwks_uri=os.environ["JWT_JWKS_URI"],
    issuer=os.environ["JWT_ISSUER"],
    audience=os.environ["JWT_AUDIENCE"],
    required_scopes=[
        "calc:read",
    ],
)
```

A JWKS-backed verifier validates token signatures against identity-provider public keys and checks issuer and audience claims. Audience validation prevents the MCP server from accepting tokens issued for another service. [FastMCP](https://gofastmcp.com/servers/auth/token-verification)

For broad third-party MCP client interoperability, token validation alone is insufficient. The MCP HTTP authorization specification expects OAuth 2.1 behavior, protected-resource metadata, authorization-server discovery, and appropriate `WWW-Authenticate` responses. [Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)

The target architecture becomes:

```text
User or service
    │
    ▼
Identity provider / authorization server
    │
    └── issues short-lived access token
                │
                ▼
MCP client
    │
    ▼
Nginx
    │
    ▼
FastMCP resource server
├── validates signature
├── validates issuer
├── validates audience
├── validates expiration
└── enforces scopes
```

Do not write a custom OAuth authorization server merely to avoid configuring an established identity provider. Authentication infrastructure is a separate security-critical product.

# 25. Coding and Security Thought Process

## Step 1: Define identities

```text
local-reader
local-writer
```

Without an identity model, authorization rules have no subject.

## Step 2: Define permissions

```text
calc:read
calc:write
```

Prefer narrow capability-oriented scopes over vague names such as:

```text
user
normal
power
admin
```

## Step 3: Authenticate at the protocol boundary

```text
HTTP bearer token
    │
    ▼
FastMCP verifier
```

Do not repeat token parsing in every tool.

## Step 4: Authorize close to the capability

```python
@mcp.tool(
    auth=require_scopes("calc:write"),
)
```

This keeps the permission attached to the operation it protects.

## Step 5: Keep TLS at the edge

```text
Client ↔ HTTPS ↔ Nginx
Nginx ↔ private HTTP ↔ Uvicorn
```

## Step 6: Do not log secrets

Log:

```text
request ID
operation name
status
duration
client identity
```

Do not log:

```text
bearer token
private key
authorization header
full request payload
```

## Step 7: Separate protection layers

```text
TLS
└── protects data in transit

Authentication
└── establishes identity

Authorization
└── limits capabilities

Rate limiting
└── limits request arrival rate

Validation
└── checks input contracts

Logging
└── supports diagnosis and audit
```

No single layer replaces the others.
